# Правила работы с кодом

Проект реализует учебное ТЗ из `REQUIREMENTS.txt`. Production backlog описан в README и не заменяет обязательные требования задания.

- PHP: PSR-4 и соглашения Laravel; формат проверяет Laravel Pint (`composer lint`), исправляет `composer format`. Изменение бизнес-полей и успешного статуса операции остаётся одной SQL-транзакцией. Новые пути применения данных должны сохранять блокировку сделки, сравнение внешних версий и fencing token.
- React/TypeScript: strict TypeScript, рекомендованный preset Biome, правила hooks и зависимостей эффектов. `npm run lint` отклоняет ошибки и предупреждения. Дополнительные `reload`/`revision` в dependencies намеренно запускают повторную загрузку; проверка отсутствующих зависимостей остаётся включена. Три локальных исключения a11y объяснены рядом с кодом: фокус в явно открываемой форме, семантика таблицы при mobile CSS и скрытые нефокусируемые skeleton-строки.
- Сохраняйте cleanup для запросов и timers. Проверяйте, что поздний GET не отменяет подтверждённый PATCH в состоянии интерфейса. `npm run test:regression` проверяет три порядка ответов с подменённым API и не обращается к рабочей БД.
- Тесты БД разрешены только для PostgreSQL `crm_test`. Guard разбирает эффективный DB_URL и все read/write реплики до подключения; PHPUnit принудительно сбрасывает DB_URL. Не отключайте guard для обхода ошибки окружения.
- Проверяйте границы, ошибки и конкурентное поведение содержательными тестами. Правки существующих гарантий требуют регрессионного сценария. Форматирование проверяют инструменты, а не ручное ревью.
- Не добавляйте секреты, `.env`, реальные персональные данные, vendor, node_modules и dist. Аудиты зависимостей: `composer audit --locked`, `npm audit`. Перед публикацией проверьте отслеживаемые файлы скриптом `python scripts/check-secrets.py` и историю Gitleaks с `--redact`.

GitHub Actions запускает те же проверки. HTTP smoke создаёт уникальные синтетические записи; очищение volumes выполняется только в одноразовом CI-окружении. Физическая потеря диска, production-нагрузка и полноценная проверка всех assistive technologies этим pipeline не моделируются.
